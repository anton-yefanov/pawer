# Releasing Pawer to the App Store

`ios/` is gitignored and regenerated by prebuild, so every release starts from `app.json`
and rebuilds the native project. The steps below are ordered because several of them undo
each other.

## 1. Versions live in app.json

- `expo.version` is the App Store version string (`1.0.1`).
- `expo.ios.buildNumber` must increase on every upload that reuses a version string.
  Apple rejects a redundant binary, not a redundant version.

Bump both, then confirm they landed in `ios/Pawer/Info.plist` *after* prebuild —
`CFBundleShortVersionString` and `CFBundleVersion`. If they still show the old values,
prebuild did not run.

## 2. The clips have to be on disk before anything else

```bash
find assets/exercise-videos -name '*.mp4' | wc -l   # expect 412
npm run videos:pull                                  # only if short
```

`assets/exercise-videos/` is gitignored and lives in Vercel Blob. A missing clip is a
Metro resolution error on the generated media map, not a warning.

## 3. Prebuild

```bash
npx expo prebuild -p ios --clean
```

This is the only thing that applies `ios.privacyManifests` from `app.json`.
`expo run:ios` writes the template `PrivacyInfo.xcprivacy` instead and says nothing, which
is how a build reaches review with an empty manifest.

Verify afterwards:

```bash
grep -c NSPrivacyCollectedDataTypeProductInteraction ios/Pawer/PrivacyInfo.xcprivacy
```

## 4. pod install fails when LANG is unset

Prebuild reports **exit code 0 even when its `pod install` step crashed**, so the failure is
silent. The crash looks like:

```
Unicode Normalization not appropriate for ASCII-8BIT (Encoding::CompatibilityError)
```

That is CocoaPods reading a UTF-8 path under a nil locale. Non-interactive shells here have
no `LANG`. Re-run the install explicitly:

```bash
cd ios && LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 pod install
```

Read the tail of the prebuild output rather than trusting its exit code.

## 5. Put the Sentry auth token back

Every prebuild regenerates `ios/sentry.properties` **without** `auth.token`. The archive
still succeeds without it; the only symptom is that production stack traces arrive
unsymbolicated, months later.

The value lives in `.env.local` as `SENTRY_AUTH_TOKEN`. Append it as its own line —
the generated file has no trailing newline, so a naive `>>` glues `auth.token=` onto the
end of the preceding comment and Sentry silently ignores the key.

```bash
awk -F= '{print $1}' ios/sentry.properties   # expect auth.token on its own line
```

## 6. Unlink the local StoreKit file

```bash
npm run storekit:off
```

`npm run storekit` points the scheme at `Pawer.storekit` for local purchase testing, and
prebuild is a natural moment to have re-run it. A shipped build must talk to the real
App Store, so run the unlink unconditionally and confirm no `storeKitConfiguration` remains
in `ios/Pawer.xcodeproj/xcshareddata/xcschemes/*.xcscheme`.

## 7. Archive

Xcode is the reliable path, and Organizer is where the upload lives:

```bash
open ios/Pawer.xcworkspace
```

Scheme **Pawer**, destination **Any iOS Device (arm64)** — Archive is disabled on a
simulator destination. Then Product → Archive → Distribute App → App Store Connect →
Upload.

The command-line equivalent, when a hands-off build is wanted:

```bash
xcodebuild -workspace ios/Pawer.xcworkspace -scheme Pawer \
  -configuration Release -destination 'generic/platform=iOS' \
  -archivePath build/Pawer.xcarchive archive
```

**Uploading is the user's call, not something to do unprompted** — it is irreversible and
public. Ask before running `xcrun altool` / `notarytool` or clicking Upload, and note that
it needs an App Store Connect API key or app-specific password that may not be configured.

So **end every release by handing over this command**, whatever else was done — there is no
CLI that opens Distribute App, and opening the archive is the shortest path to it:

```bash
open build/Pawer.xcarchive
```

That launches Xcode's Organizer with the new archive already selected; **Distribute App** is
on the right. `open ios/Pawer.xcworkspace` then Window -> Organizer is the long way round.

## 8. After the upload

Processing takes 5–30 minutes and ends in an email. Then in App Store Connect: select the
build on the version, and remember that **description, keywords and screenshots are frozen
once a version is live** — they only change with a new version. `Promotional Text` is the
exception and can be edited at any time without review.

Check the subscription products' own status too. The app going live does not imply the
IAPs were approved.
