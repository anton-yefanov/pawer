## Comments and docs

Write code that explains itself; don't narrate it.

- No comments that restate the code, label sections, or describe what a function obviously does. Comment only a non-obvious *why* — a workaround, an invariant, a gotcha that would otherwise get "fixed".
- No JSDoc/TSDoc blocks on internal code. Types are the documentation.
- Don't create new markdown files (READMEs, summaries, migration notes, plans) unless asked. Existing docs — this file, AGENTS.md, IMPLEMENTATION_PLAN.md — get updated only when a change makes them wrong.
- In chat, report what changed in a few lines. No recaps of code that's already visible in the diff.

## Commands

```bash
npm run ios          # expo run:ios — dev build, NOT Expo Go (native modules)
npm start            # metro only, for an already-installed dev build
npm run lint         # expo lint (eslint-config-expo flat config)
npm run typecheck    # tsc --noEmit

npm run db:generate      # drizzle-kit generate — after any src/db/schema.ts edit
npm run build:seed       # rebuild src/db/seed/exercises.json from the purchased metadata.json
npm run build:emoji      # rebuild src/constants/emoji-data.ts from emoji-datasource
npm run build:images     # vendor posters -> shipped webp (see §Assets)
npm run build:videos     # vendor mp4 -> assets/exercise-videos/, ~45 min (see §Assets)
npm run videos:pull      # mirror the encoded clips down from Vercel Blob — needed before prebuild
npm run videos:push      # the other direction, after a re-encode
```

There is no test runner in this project. Verification is `npm run typecheck && npm run lint` plus running the app.

`ios/` is gitignored — the native project is generated by prebuild, so never hand-edit it; change `app.json` instead.

## Architecture

Expo SDK 57 / React Native 0.86 / expo-router with `typedRoutes` and the React Compiler enabled. iOS-first. Local-first: nothing is fetched at runtime. The library, the exercise clips, logging, history and analytics all work with the network off.

**IMPLEMENTATION_PLAN.md is the spec.** It sets scope, the paid/free split, and several non-negotiable technical decisions. Read the relevant section before building a feature, and don't build things listed under "Explicitly out of v1".

### Data layer

`src/db/` — expo-sqlite + Drizzle.

- `client.ts` — the single `db` instance. `enableChangeListener: true` is what makes `useLiveQuery` re-render on writes; screens use `useLiveQuery` and never refetch by hand.
- `provider.tsx` — `DatabaseProvider` runs migrations then seeds before any screen renders. It wraps the whole app in `src/app/_layout.tsx`.
- `schema.ts` — migrations are generated, never hand-written. Edit schema → `npm run db:generate` → commit the new `drizzle/*.sql` + `drizzle/meta`.
- `seed.ts` — idempotent upsert keyed on `sourceId`. Bump `SEED_VERSION` when `seed/exercises.json` changes so installed apps re-seed.

Metro/Babel are configured specifically for Drizzle migrations: `metro.config.js` adds `sql` to `sourceExts` and `babel.config.js` adds `inline-import` for `.sql`. Don't remove either.

### Schema invariants

These are cheap now and painful to retrofit — hold them for every new table:

- UUID string primary keys (`newId()` from `src/db/id.ts`), never autoincrement.
- Spread the shared `timestamps` (`createdAt`/`updatedAt` epoch ms, nullable `deletedAt`) and soft-delete instead of deleting.
- **Weights are kilograms and distances are metres in the database, always.** Pounds and miles exist only between `src/lib/units.ts` and the screen.
- `personal_records` is append-only: one row per achievement, never updated in place, so a badge stays on the workout that earned it. The standing record is `MAX(value)` per exercise and kind over rows with `deleted_at IS NULL`. `src/lib/personal-records.ts` is the only place that decides what counts as a record.
- A set's meaning comes from its exercise's `trackingType`, never from which columns happen to be non-null. `src/lib/tracking-types.ts` is the only place that switches on it — columns, headers, "Previous" text, validity and volume all read from `TRACKING` there. Assisted exercises store a *positive* magnitude in `weightKg`; only the displayed sign differs.
- `exercises.search_text` is derived, never authored: `buildSearchText()` in `src/lib/exercise-search.ts` is the only thing that writes it, and anything inserting or renaming an exercise recomputes it. Its search vocabulary comes from `exercises.tags`, generated for the seed by `scripts/exercise-tags.mjs` — add gym slang and abbreviations to the alias table there, not to exercise names.

### Assets

Illustrations are never referenced by path from a screen. `src/lib/exercise-media.ts` is the only resolver (Metro needs static `require` literals, so any real lookup map must be generated or written out).

**Every exercise is a video, and the video ships in the app.** The purchased library at `assets/new_exercises_data/` ships 412 clips, 412 posters and `metadata.json`; the vendor originals are 889 MB and gitignored. `npm run build:videos` re-encodes them to `assets/exercise-videos/<tag>/<slug>.mp4` — HEVC 1084×600 CRF 26, no audio, ~106 MB for the set — and `npm run build:images` copies the posters and cuts a 150px square thumb from each, writing `src/lib/exercise-media-map.ts` as it goes.

**Clips are ordinary bundled assets.** `EXERCISE_MEDIA[slug].video` is a `require()` of the mp4, so Metro pulls all 412 into the binary the same way it pulls the posters — no download, no progress UI, no network path to fail. That costs ~106 MB of app size, which was a deliberate trade against the complexity of on-demand delivery: an earlier version shipped the clips as twelve iOS On-Demand Resource asset packs and it is gone, so don't reintroduce `NSBundleResourceRequest`, a config plugin, or a download provider.

The posters ship too, at 3.7 MB. A clip needs a moment to produce its first frame, and `ExerciseVideo` draws the still underneath until `onFirstFrameRender` fires, so a sheet never opens on a black rectangle.

`<tag>` survives as the directory the encoder writes into (`assets/exercise-videos/<tag>/<slug>.mp4`) and comes from `groupOf()` in `scripts/exercise-taxonomy.mjs`. It is now only a filing convention — nothing at runtime reads it, because the generated `require` path already encodes it.

**Vercel Blob is the store, not git.** `assets/exercise-videos/` is gitignored; `npm run videos:push` mirrors it into the `pawer-blob` store and `npm run videos:pull` brings it back. A clean clone needs the pull before it can bundle at all now, not just before prebuild — a missing clip is a Metro resolution error on the generated map. `npm run build:images` warns for each one it can't find, which is the earlier and friendlier version of the same failure.

`scripts/exercise-taxonomy.mjs` is the one place the vendor's vocabulary becomes ours: it maps the sixteen muscles onto the twelve browse groups and decides which pack a clip ships in. The seed builder, the video builder and the image builder all read it, so a group, a folder and a `primaryMuscles` value cannot disagree.

### Observability

`src/lib/observability.ts` is the only place that touches Sentry, and it is the reason a
failure in this app is never silent. `initObservability()` runs once from `src/app/_layout.tsx`;
the DSN lives in `app.json` `extra.sentry.dsn` beside the PostHog key, and `REPORT_IN_DEV`
mirrors `telemetry.ts`'s dev switch.

Four entry points, and nothing else calls `Sentry.*` directly:

- **`attempt(scope, promise, notice?)` replaces `void someDbAction()`** and resolves to whether
  the write landed. This is the important one — a `void`ed write that rejects changes nothing on
  screen, so the checkmark just doesn't tick and the typed weight reverts on the next live
  query. Pass the notice whenever the user typed or tapped the thing; leave it off for a
  preference read.
- **`guard(scope, promise, notice?)`** is the same for a promise whose *value* you need;
  `undefined` means it failed. Never use it on a `Promise<void>` — that resolves to `undefined`
  on success too, so every write would read as a failure.
- **`guardSync(scope, fn)`** for native calls that throw through JSI rather than rejecting —
  `workoutActivity.start`, `Purchases.configure`, registering the Live Activity.
- **`report(scope, error, tags?)`** when there is nothing to await.

`scope` is a closed union and doubles as the Sentry fingerprint, so events group by the
operation that failed rather than by whichever Drizzle frame threw.

Two things hold the privacy story together, and the Settings footer states both. `beforeSend`
strips the IP address, device name and any `file://`/`ph://` path down to a basename, and
`track()` in `telemetry.ts` doubles as the breadcrumb source — its event map is already flat
enums and counts, so no free text ever reaches Sentry. **Sentry is deliberately not covered by
the "Share Anonymous Usage Data" toggle**: that switch is analytics, crash reports are always
sent, and the footer says so.

There is one blind spot by construction: the `'widget'` function in `live-activity-layout.tsx`
is re-evaluated in the extension's own runtime, where Sentry does not exist. A throw there is
invisible everywhere, so that layout validates its props instead of relying on reporting.

Source maps and dSYMs upload from the Xcode build phases the `@sentry/react-native/expo` plugin
adds during prebuild. They need `SENTRY_AUTH_TOKEN`, which lives in `.env.local` and is copied
into `ios/sentry.properties` — **both gitignored, and `ios/sentry.properties` is regenerated
without the token by every `expo prebuild`, so it has to be put back.** Without it the build
still succeeds and every production stack trace arrives unsymbolicated.

### Live Activity

An active workout mirrors itself onto the Lock Screen and Dynamic Island through `expo-widgets`, iOS only. `src/lib/live-activity-layout.tsx` is the layout, `src/lib/live-activity.tsx` the driver mounted at the root inside `RestTimerProvider` — the activity has to outlive the logger screen, which unmounts on a tab switch. The `ExpoWidgetsTarget` extension in `ios/` is generated by the config plugin from the `app.json` entry; never add it by hand.

Two rules hold it together. **A `'widget'` function is stringified by Babel and re-evaluated in the extension's own runtime**, where the only bindings are the `@expo/ui/swift-ui` globals — it can close over nothing, so every colour, unit and string arrives pre-formatted as a prop. And **neither clock is ever pushed**: elapsed time and rest are both `Text` with a `timerInterval`, off `workouts.startedAt` and the rest timer's `endsAt`, ticked by SwiftUI — the same trick `src/components/workout/rest-timer-button.tsx` uses in-app. `dateStyle="timer"` is the trap to avoid: it reads `1:17:26` in the Dynamic Island but "1 hour, 17 minutes" in the banner. Updates carry only set/volume/exercise state and are shallow-compared first, because set rows are rewritten on every debounced keystroke and ActivityKit throttles chatty callers.

Sizing is the other trap. Every view in a slot stretches to fill unless given an explicit `frame` — that is what drags the Dynamic Island pill across the whole screen — and `fixedSize` does not help, it collapses a `timerInterval` to nothing. A clock's frame must also clear the width SwiftUI reserves for the *widest* value in its range, not the value on screen. The compact pill can never be narrower than the sensor housing between its two halves, so it carries only glyphs; the clock lives in the expanded layout.

### UI conventions

- Path aliases: `@/*` → `src/*`, `@/assets/*` → `assets/*`.
- Colors come from `Colors` in `src/constants/theme.ts` via `useTheme()`; no hardcoded hex in components. Text has three tiers — `text`, `textSecondary`, `textTertiary` — and a caption that is supplementary to something already on screen takes the third.
- **Type is a closed scale.** `Type` in `src/constants/theme.ts` holds the eleven iOS text styles, named for their HIG counterparts, and `ThemedText` is the only thing that reads it: a caller picks `type="footnote"`, never `fontSize: 13`. A component that writes its own size is the bug the scale exists to prevent: under the previous scale, which had no role for one, "section header" drifted into three unrelated treatments and "screen title" into six. `weight` overrides a role's default weight and `numeric` turns on `tabular-nums`, which every clock, duration and column-aligned figure needs or its digits shift as they tick. `letterSpacing` is Apple's SF Pro tracking table and is `Platform.select`ed to iOS, because Nunito is drawn with its own metrics. `ThemedTextInput` takes `body` from the same place, minus the `lineHeight` — a field centres its glyph box inside one and clips descenders.
- **A screen is a grey page carrying white cards** — grouped-list style, the same on all tabs and in sheets. `background` is the page (and the stack's `contentStyle`), `surface` is anything raised off it (a card, a list row, a floating control), `backgroundElement` is a fill *inside* a surface (divider, input, chip) and never a card itself. Never invert this for a single screen.
- The one exception: a screen that is a **full-bleed list of edge-to-edge rows** (the exercise library, a template's exercises) is white throughout — the rows are already `surface`, so the page is too, `contentStyle` included. A grey page there would only show as a band behind the floating search row, the sheet's transparent header and the footer, which is exactly the seam this avoids.
- A template or folder card's cover is a mesh gradient, not a theme token: `templates.color` / `folders.color` hold an id from `src/constants/card-colors.ts` (null means grey), `cardGradient()` in `src/lib/card-gradients.ts` is the only thing that turns one into colours, and `CardCover` in `src/components/templates/card-cover.tsx` is the only thing that draws one. `expo-mesh-gradient` renders nothing below iOS 18, so the flat fill `CardCover` paints under the mesh is the cover on older devices, not a backdrop. The covers are pastel in both schemes — the artwork sits directly on them — so there is no dark variant. App-shipped templates ship a hue from the seed and keep it; users set their own through the Customize sheet (`src/app/(workout)/customize.tsx`).
- **A cover's artwork is exercise previews, up to three emoji, or a photo, stored as JSON in `templates.artwork` / `folders.artwork`.** `src/lib/card-artwork.ts` is the only thing that parses or writes that column, and it is a discriminated union rather than a bare id so pre-defined stickers can join without another migration; `null` is the bare gradient, which is what Clear produces. `ArtworkLayer` in `src/components/templates/artwork-layer.tsx` draws it and owns every sizing table, which is why each caller hands it a `coverHeight` instead of letting it measure — a measured row draws a frame late and a grid of those flickers on scroll. `exercises` carries no payload: the cover reads the template's own exercises, so it keeps up as they are added and reordered, and a card passes their `sourceId`s down beside the artwork. It is what a new template and every app-shipped one start with; the three tabs in the Customize sheet are the artwork's source, each holding its own draft. A folder wears the same emoji on the front panel of its illustration (`FolderArt` in `src/components/templates/folder-art.tsx`), through the same sheet with neither the Exercises nor the Media tab — so it shows no tabs at all.
- Emoji go through `src/components/emoji.tsx`, never a bare `Text`. The system emoji font on iOS *is* Apple Color Emoji, so nothing is bundled and it stays sharp at any size; Android draws Noto until an `emoji.android.tsx` sibling swaps in Apple artwork, and no caller changes. The picker's vocabulary is `src/constants/emoji-data.ts`, generated by `scripts/build-emoji.mjs` (`npm run build:emoji`) — never authored.
- Tabs are `expo-router/unstable-native-tabs` (`src/components/app-tabs.tsx`), with a `.web.tsx` sibling for web — the `.web.tsx`/`.ts` split is the pattern for platform divergence here.
- Drag and drop (`src/components/templates/template-drag.tsx`) is hand-rolled on gesture-handler + Reanimated. dnd-kit is DOM-only; `react-native-drax` was tried and dropped — it renders the dragged view into a full-screen overlay positioned from a measured provider offset, which is wrong under a native stack inside native tabs. Here the card stays in the grid and moves by gesture *translation*, so no coordinate space is ever converted. A drop writes to SQLite and `useLiveQuery` re-renders; there is no drag state in React. `src/components/workout/exercise-reorder.tsx` is the same engine for the exercises inside a workout: a long press on a name folds every exercise's sets away, which is what makes the rows uniform enough for that index arithmetic to hold.
